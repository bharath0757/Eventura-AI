## First-screen discoverability

The existing visual identity and primary creation action are retained. Hero copy explicitly names weddings, birthdays, community events, budgets, timelines, vendor checklists, ideas and optional Gemini guidance. Browser tests check that this description fits within the initial desktop/mobile viewport, that the primary CTA opens the wizard directly, and that each category card selects its corresponding workflow. The wizard review explains that the starter plan is deterministic and where to request AI assistance afterwards. The dashboard names its existing section **Your AI planning assistant**.

## Context, privacy and honest source labels

The bounded prompt includes the selected event's category, date, budget, guests, style, priorities, dietary/access needs, category details and current plan; record IDs, unrelated events and retained history are excluded. Structured output is validated with Zod and category checks. Gemini does not control final monetary amounts. Only user confirmation persists a validated proposal. Default Gemini 3.8 uses stateless `store: false` interactions; a production Secret stays server-side.

Ordinary tests use explicit mocks or no-key rule-based fallback. The live smoke runner validates genuine source labels and stops at the first failure. Its results and current CI/publication status are stated in the remediation report. No evaluation score, successful inference, live price, booking or cross-device persistence is implied by this matrix.
